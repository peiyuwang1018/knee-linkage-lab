Knee Linkage Lab

A small analytical workbench for a planar knee transmission. Python computes the geometry and forces; the browser displays them. The layout follows the compact parameter / canvas / plot pattern of PySLVS. No PySLVS code or solver is used.

Model and parameters · Initial findings · Local setup and reproduction

Window layout

Wide landscape windows show parameters, mechanism and analysis side by side. Narrower or portrait windows stack the mechanism above the plot and force ranges. In small windows, use Parameters to open the parameter drawer; click its backdrop or press Escape to close it. Parameters scroll independently. Plots redraw to fit the available space without changing the selected rod, time or configuration.

Core curve values and force ranges stay in the analysis area. Use Details or Joint & support details for additional joint and support values. The analysis area scrolls when the available height is insufficient. This display update does not change the solver or load model.

1. Start with the default example

  1. Keep n = 2, spacing 90°, axis distance 300 mm, crank radius 60 mm and shank length 340 mm.
  2. Use total mass 80 kg, leg share 0.5 and constant load factor 1. The vertical ground force on this leg is 392.4 N.
  3. Play the cycle or drag the time slider. Positive rod force is tension; negative is compression. Line patterns identify rods.
  4. Compare n = 1, 2 and 3. For n ≥ 2, dependent lengths are locked to preserve the parallelogram.
  5. Use Save config for reproducibility and Export CSV for time histories. A config contains all assumptions and can be reopened.

Direct controls and force overlays

Click 1, 2 or 3 in Rod groups: the number of filled cells is the group count. The two handles in Knee angle range set its lower and upper bounds without crossing. Use the Start / End knee angle fields for exact values and motion direction. Dragging a bound preserves that direction; equal bounds describe a fixed pose. Slider arrow keys change a bound by 1°.

Click R1 / R2 / R3 below the mechanism or in the chart legend to toggle individual force overlays. Select any combination; All selects every rod and Clear clears overlays. Unselected rods and curves retain 55% opacity; the thigh and shank retain 70%. Geometry is never hidden by selection. All arrows appear on the complete mechanism.

Display colors

The Color / Mono sliding switch changes the display without a menu. R1 is slate blue, R2 clay, and R3 sage; the thigh is ochre and the shank muted plum. Each group keeps the same color across crank arms, pins, couplers, force curves and legends. Dashed patterns remain in both modes. Color identifies parts, not tension or compression. The preference is remembered locally, and SVG export keeps it.

2. Geometry and signs

O is both the input axis and the hip in this first model. K is the knee axis. F is the fixed ground contact. The axis distance d also serves as the thigh length. A separate motor offset is not included. The motor housing is attached to the thigh; a torso-mounted motor requires hip–knee motion and power coupling.

The signed knee angle q is zero when the thigh and shank align. Negative and positive values bend the knee to opposite sides. Output crank angle β = q + δ in the thigh frame. δ is the clocking between the shank and the first crank arm, not a second independent joint.

For multiple rods: both discs have the same radius and matching phases; every coupler has length d. Three rods use 0°, α, 2α with adjustable α from 60° to 120°. At 120°, the phases are 0°, 120°, 240°. The input/output angular ratio is 1:1. Extra rods redistribute load and improve transmission near individual rod dead points; they do not multiply torque.

Curve monitor and force ranges

The legend displays every curve's value at the current cursor. Click a rod legend to toggle its force overlay without changing time or other selections; unselected rods remain at 55% opacity. Click or drag the plot to pause and inspect the nearest sampled frame. Cursor dots mark the curve values; time and knee angle appear above. Arrow keys step one frame (Shift: ten); Home/End jump to endpoints.

Force ranges is always visible below the plot. Min + / Max + are the smallest/largest positive samples. Min − is strongest compression (most negative); Max − is the negative sample closest to zero. Click an extremum to add its rod to the current selection and jump to its first occurrence. Hover a value for time and knee angle. A missing sign displays —.

Ranges use valid, nonzero samples (|N| > 10⁻⁶ N). Labels distinguish the full cycle, guarded preview and partial valid data. Near-zero minima depend on sampling; if a continuous curve crosses zero, its nonzero magnitude can approach zero arbitrarily closely. These are sampled observations, not bounds on an exact continuous trajectory. Additional joint/support values are available under Details or Joint & support details.

Single-rod guard

Dead-center margin (default 5°) is the minimum acute crank-to-rod angle at either pin, not a fixed offset in knee angle. The preview uses the first continuous admissible interval in the requested direction. It never animates across an excluded zone. The quintic motion is rebuilt with zero endpoint speed and acceleration; the requested angles remain unchanged. A limited preview cannot pass the original task in Scan. No admissible interval disables playback.

Reading rod force arrows

Arrows show external forces on each selected rod: outward in tension, inward in compression. A is the input pin, B the output pin; the forces on the discs are opposite. Every selected group keeps its own color. Arrow length uses one fixed scale across all rods and the whole cycle. Zero force has no arrow; invalid loads have no force vectors. Changing selections while playing is supported. SVG exports the current mechanism with all selected overlays; CSV includes Fx/Fz vector components and requested/preview motion ranges.

3. Why rigid rods need a load-sharing assumption

With several parallel load paths, moment balance alone cannot uniquely assign each rod force. This tool uses a small axial-compliance model with stiffness kᵢ, rigid discs and supports, zero preload and zero clearance.

Σ bᵢ Nᵢ = τknee
Nᵢ = kᵢ bᵢ τknee / Σ(kⱼ bⱼ²)

bᵢ is the signed moment arm of a tensile rod force about K. This solution minimizes the elastic strain energy ΣNᵢ²/(2kᵢ). It is also the load distribution obtained by holding the input and allowing a small elastic output deflection. Forces are not divided equally by rod count.

The geometry canvas shows the nominal rigid position. It does not exaggerate or display elastic deflection. A twist above 1° triggers a small-deformation warning. Absolute stiffness is a placeholder until the real rod sections and joints are known. Changing every stiffness by the same factor changes twist but not force sharing.

4. Loads and motion

ModeGround force on this legMeaning
Constant κFz = share × M × g × κPrescribed load envelope. Playback duration changes speed, but not this force.
COM trajectoryFz(t) = share × M × [g + z̈(t)]All effective mass is lumped at the hip. Hip height follows leg geometry; links are massless.

The foot remains fixed at (0,0), and the hip moves vertically above it. Both thigh orientation and hip height change. Knee angle follows a smooth quintic curve from start to end and back, with zero speed and acceleration at each endpoint. One-way duration T means total cycle duration 2T.

h(q) = √(d² + s² + 2ds cos q)
z̈ = h″(q) q̇² + h′(q) q̈

If Fz ≤ 0, the imposed motion would need a pulling ground contact or lose support. That frame is invalid; force is not silently clamped to zero. A non-jumping motion can still require force above body weight while accelerating upward.

Human sit-to-stand research reported group mean peak total vertical GRF of 1.2263 BW and 1.1614 BW (Piano et al., 2020, Table 3). This is context, not a robot limit. The tool's 1.0 / 1.2 / 1.5 factors are selectable engineering scenarios, not validated safety factors.

5. What the reaction forces mean

Input support and knee support are the resultant reactions at the ideal revolute axes. Pin force at either end of an ideal massless coupler has magnitude |Nᵢ|. These are not the loads of individual bearings in a bearing pair, local contact pressure, pin bending stress or fatigue life. Three-dimensional spacing and support stiffness are needed for those.

Input torque is at the input disc. If a motor module already has an internal gearbox, this is its output-shaft requirement. No gearbox efficiency, current limit, thermal limit or extra reduction is applied here.

6. Scan a bounded design space

Open Scan, enter comma-separated values, and set limits. A zero limit is disabled. The scan uses compatible parallelograms for all n, including n = 1. It rejects sampled closure/contact failures, singular single-parallelogram crossings and user limit violations. Candidate rows can be loaded back into Model.

Ranking uses peak absolute rod load. The Pareto flag considers only rod load and crank radius. It does not mean an optimal robot. Larger cranks naturally lower axial forces, so package size, mass, strength and clearance still need external constraints. Changing d or s also changes achieved hip height; use the top/low height limits to keep candidates relevant to the same task.

Refine promising ranges and increase cycle samples before selecting a candidate. General single-four-bar motion is sampled; the program does not prove continuous branch feasibility for arbitrary geometry.

7. Model limits and next stages

  • No link mass, rotational inertia, impact, backlash, preload, friction, 3D collision or elastic bending.
  • No whole-robot balance, lateral load transfer or proof that a controller can execute the trajectory.
  • Knee reversal crosses the straight-leg singularity; it is a geometry study until joint limits, collisions and control are checked.
  • Next: calibrated axial stiffness → packaging and collisions → real component loads → multibody / experimental comparison.

For a general multibody cross-check, PyChrono provides joints, motors, springs and contacts. This first version uses an inspectable analytical solver so that signs, assumptions and load sharing remain explicit.
